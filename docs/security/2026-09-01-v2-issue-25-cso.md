## 1. What was audited
The final migration contraction (PRD Phase 11, manifest §4): removal of all superseded V1 product paths and the storage-level drop of 30 V1 tables, with verification that exactly one product architecture remains.

## 2. Security scope
High-risk by classification (mass deletion + destructive migration + binding/secret removal). No visitor-facing surface was added; the public surface shrank from 19 routes to 8.

## 3. Attack-surface summary
- Route table (verified): 7 V2 routes + 1 internal KIE ack. All V1 routes (fluentforms webhook, 7 jobs routes, contact submit, reference upload, GitHub webhook, deploy-smoke, candidate-validation) are gone — no production V1 fallback exists.
- Bindings: `WEBSITE_AGENT` DO (+ DO migration), `SITE_BUILD_WORKFLOW` workflow removed from wrangler + `env.d.ts`. `WebsiteBuildWorkflow` is the single orchestrator.
- Secrets/vars removed from the runtime contract: `SMTP2GO_API_KEY`, `GITHUB_TOKEN`, `GITHUB_WEBHOOK_SECRET`, `GITHUB_REPO_*`, `APPROVAL_SECRET`, `APPROVAL_TIMEOUT_DAYS`, `MAX_REVISIONS`, `VISUAL_QA_MIN_SCORE`, `INTERNAL_NOTIFICATION_EMAIL`, `CANDIDATE_VALIDATION_*`. Zero code references remain (grep-verified; the single `SMTP2GO` hit is an explanatory comment in `publish.ts`).
- Destructive migration: 30 `DROP TABLE IF EXISTS` statements.

## 4. Findings

### Verified properties (no finding)
- **Destructive-migration safety:** the drop list was cross-checked programmatically against the 26 V2 tables — zero overlap, and every non-V2 table in migrations 0001–0029 is covered (no orphans). The full test suite runs migrations 0001→0030 in order on fresh storage and stays green (25 files / 149 tests), proving the surviving schema is exactly the V2 set.
- **No V1 fallback / no switches:** grep for feature-flag/legacy-mode/`useV1` patterns returns nothing; the V1 render/generator/prompt-registry/mail paths no longer exist to fall back to.
- **Deploy surface:** `publish.ts` now exports only the assets-only deploy path plus shared helpers — the contact-worker/SMTP2GO injection path is deleted, so the H1 class of finding is structurally impossible.
- **Secret hygiene:** no secret material was ever committed; the removed secrets exist only as live Worker secrets in the deployment environment.

### W14 — Delete retired production secrets operationally (Watch item, Medium — operational follow-up, not code)
`wrangler secret delete SMTP2GO_API_KEY` (and the GitHub/APPROVAL/CANDIDATE_VALIDATION secrets if set) must be run against production so retired credentials stop living in the deployed Worker. Code no longer reads them; this is pure credential-hygiene follow-up for the deploy operator.

### W15 — Unauthenticated internal KIE ack endpoint (Watch item, Low)
`POST /api/internal/kie-callback` is now a write-free ack (parses, logs, 200). An attacker can spam log lines with junk taskIds; there is no mutation surface. Acceptable as-is; if KIE ever gates callbacks on a shared secret, verify it here.

### W16 — Retained infra keeps optional V1-shaped diagnostic fields (Watch item, Low)
`GatewayMeta` retains optional `job_id`/`client_slug` diagnostic fields and `assets.ts` keeps `visionInputDerivativeKey`'s legacy parameter names, used only by the retained vision-input/ai-gateway chain. V2 never populates them; they are diagnostic vocabulary, not product semantics. Rename opportunistically in a future infra pass.
