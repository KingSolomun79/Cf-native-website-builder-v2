## 3. Attack-surface summary

- **Public (anonymous):** `POST/OPTIONS /api/public/client-intakes` only. A
  successful call writes ONE mutable `client_intake_drafts` row — the route
  whitelists `submitter`/`business`/`designPreferences` from the body, so
  `turnstileToken`, `referenceUrl` and `referenceScreenshotR2Key` from a public
  caller are dropped before validation and can never be planted. No Site
  Generation, Build or workflow can start from this endpoint.
- **Operator:** `/admin/*` pages and `/api/admin/*` routes — every handler calls
  `requireCloudflareAccess` (both CF vars required else 503; JWT must parse,
  alg=RS256, verify against the team's published certs, unexpired, correct iss
  and exact aud). Approval/Publication deliberately stay on the HMAC
  capability-token routes — Access login is not publication authority.
- **Secrets:** `CLIENT_INTAKE_TURNSTILE_SECRET_KEY` (dedicated, no fallback to
  the generated-sites `TURNSTILE_SECRET_KEY`, fail-closed 403 when absent);
  `WEBHOOK_SECRET` reused as the rate-limit hash salt; no secret values in
  config; wrangler.jsonc commits only public JWT identifiers (team domain, AUD).
- **Background:** admin-notification cron sweep (bounded, ledger-deduped).
- **Third parties:** Turnstile siteverify (server-side, secret never exposed).

## 4. Findings

### F1 — Secrets-hygiene gate drifts from the audited secret set (Verified, Medium — tranche-introduced; REMEDIATED in this closure)
`scripts/verify-v2-secrets.mjs` treats any name outside
`required ∪ optional ∪ RETIRED` as `unexpected secret outside the audited set`
(exit 1). The 8c1d2fa secret split added `CLIENT_INTAKE_TURNSTILE_SECRET_KEY`
to the production Worker but never taught the gate the new name, so the gate
now reports a VIOLATION for the exact secret the security decision requires —
or induces an operator to "fix" the failure by deleting it, fail-closing the
live intake form (403 on every submission). **Remediation (this closure):** the
name is added to the audited profiles — production `required` (the public
intake endpoint requires it), sandbox `optional` — with a comment pinning the
reason. No runtime code changes.

### S1 (standing M1) — Unauthenticated lifecycle GETs expose Business Facts (Verified, Medium — pre-existing, carried)
Re-verified on the current tree: `GET /api/v2/site-generations/:id` and
`GET /api/v2/builds/:id` have no auth guard, and `getSiteGenerationView`
returns `facts` from the immutable submission payload (contactEmail, phone,
address, socials). Protection remains the 122-bit UUID capability URL. The
2026-09-01 CSO signed this non-blocking and conditioned remediation on
production traffic; production went live at the 2026-09-11 rollout GO with the
posture unchanged and no recorded disposition. Not a tranche regression (the
tranche neither touched nor worsened these routes; the new admin surface is
fully gated). **Disposition: carried as the top standing item — operator
decision needed.** Recommended remediation: require the existing WEBHOOK_SECRET
HMAC (or a scoped capability token) on these reads, or strip contact-bearing
facts from the public view model. Tracked here rather than silently accepted.

### S2 (standing M2) — Form-rate-limit hardening (Verified, Low-Medium — pre-existing, carried)
Generated-sites Form Service still uses check-then-act per-site+IP counting
(small concurrency overshoot) and `ip_hash = sha256(siteId:ip)` where the
unguessable per-site UUID acts as the de-facto salt; the intake endpoint's new
limiter is also check-then-act but Turnstile-gated (paid token per attempt) and
salted with `WEBHOOK_SECRET`. Bounded in practice; unchanged by the tranche.
Carried as watch.

### S3 (standing M3) — No script allowlist on generated HTML at preflight (Verified, Medium — pre-existing, carried)
Preflight remains structural (metadata, ld+json parse). Model-authored inline
`<script>` in page HTML is not deterministically blocked; the DOM-first builder
and QA-B reduce but do not eliminate the prompt-injection path from a
malicious Reference. Unchanged by the tranche. Carried; recommend an
allowlist/CSP gate as scoped follow-up work (fits #26 final verification or a
dedicated correction).

## 7. Watch items

1. `validateAndGenerateFromDraft` is check-then-act over the draft row: two
   concurrent Validate & Generate calls could both start a Site Generation
   (the conditional UPDATE keeps only one linked). Admin-only, double-click
   class. Consider making the conditional UPDATE the gate before starting the
   workflow.
2. Draft reference-screenshot upload writes to R2 before the draft-existence
   check in `setDraftReferenceScreenshot` — orphan objects on invalid draftIds.
   Admin-only.
3. `businessName` may contain control characters (JSON strings) and flows into
   notification email subjects. The Cloudflare Email Service binding takes
   structured fields (not raw SMTP headers), so header splitting is not the
   mechanism at risk; still, strip CRLF/control chars when composing subjects.
4. `public_intake_rate_limits` has no cleanup — one row per hashed-IP per
   clock hour accumulates indefinitely. Add a prune to the cron sweep.
5. `listDrafts` passes a NaN `limit` through on garbage query strings
   (admin-only 500). Clamp before binding.
6. `EDITOR_JS.serviceRow` builds inputs via `innerHTML` string concatenation;
   today it only ever receives empty strings (server rows are JSX-escaped).
   Keep untrusted values out of that path or switch it to DOM APIs.
7. Intake Turnstile siteverify does not pass `remoteip` (optional per CF;
   passing the hashed-origin IP would tighten verification).

## 8. Final security verdict
