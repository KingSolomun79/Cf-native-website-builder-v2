# CSO Security Sign-Off — Issue #29 (Capability-token gating of Approval/Rollback operator routes)

**Date:** 2026-09-01
**Scope:** Working tree vs `c1fa881`: `src/lib/operator-capability.ts` (new), `src/lib/crypto.ts` (exported `timingSafeEqualStrings`), `src/routes/v2.approval-create.ts` (new), `src/routes/v2.rollback.ts` (new), `src/index.ts` (route table), `src/domain/publication.ts` (conditional rollback state flip), `src/env.d.ts` (`OPERATOR_CAPABILITY_SECRET`), `scripts/mint-operator-capability.mjs` (new), `wrangler.test.jsonc`, `tests/v2-operator-capability.test.ts` (new).
**Reviewer:** AI-assisted CSO pass (morabeza-cso skill). Not a substitute for an external audit.

## 1. What was audited
The first HTTP exposure of the two human release actions — Approval (`POST /api/v2/build-versions/:buildVersionId/approval`) and Rollback (`POST /api/v2/sites/:siteId/rollback`) — and the offline minting path for their capability tokens. This closes W4 from the #15 CSO pass.

## 2. Security scope
High-sensitivity by classification: new **authenticated operator routes performing state mutations** (release authority, published-site state), plus a new HMAC secret (`OPERATOR_CAPABILITY_SECRET`, Worker secret — not a var, not in `wrangler.jsonc`).

## 3. Attack-surface summary
- Two new POST routes, the only HTTP mutation surfaces for release state (grep audit: `publishApprovedBuildVersion` has **no production caller** — publication remains an internal service until it gets its own gated surface).
- Token verification (`verifyOperatorCapability`): HMAC-SHA256 over a versioned canonical string (`v2opcap/1:…`), base64url JSON payload, timing-safe compare, strict charset validation of bound values (no `:` delimiter smuggling), `exp` must be a safe integer within `(now, now + 60 min]`, token length ≤ 4096, **fail-closed when the secret is unset**.
- Minting: offline only (`scripts/mint-operator-capability.mjs`, Node). **No minting route exists** — grep audit: `signOperatorCapability` is referenced by no route/handler; `src/index.ts` registers only the two consuming routes.
- Generated Sites: static-assets-only workers (no bindings, no secrets — pinned by `tests/v2-static-deploy.test.ts`), structurally unable to read the secret or reach the mint function.

## 4. Findings

### Verified properties (no finding)
- **Deny-by-default across all classes:** missing header, garbage, wrong-secret signature, tampered claims (claim swap keeps the old sig → invalid), expired, beyond-ceiling TTL, and unset secret all yield 401 with zero rows written (tests assert approval rows / published state unchanged).
- **Binding sufficiency per the #15 prescription:** approve binds `buildId + buildVersionId + artifactManifestHash + action + exp`; rollback binds `siteId + fromBuildVersionId (the current Published Version at mint) + action + exp`. Cross-version, cross-site, stale-rollback and wrong-action tokens are all 403 `CAPABILITY_INSUFFICIENT`.
- **Authorization strictly precedes mutation:** both routes verify credential, then action, then resource bindings, and only then call the mutating service; denials are decided before any service call.
- **Stale-rollback protection:** a token minted while v2 was current is refused after v3 publishes (from-version mismatch → 403), so the operator must re-review current state.
- **No forgery oracle:** every pre-signature failure is indistinguishable from a signature failure (single null result); 403 appears only for validly signed tokens.
- **Cross-signer agreement:** Worker (WebCrypto) and mint-script (node:crypto) outputs are pinned byte-for-byte by known-answer vectors in the test suite.

### F1 — Rollback TOCTOU between authorization read and state flip (Medium — fixed in-diff)
The route authorized against a read of `site_published_state`, then `rollbackPublication` re-read and mutated; a publication landing in the window between could redirect which version gets restored. **Fixed:** `rollbackPublication` now accepts `expectedCurrentBuildVersionId` and performs the state flip as a conditional update (`AND current_build_version_id = ?`); zero rows changed ⇒ `NO_ROLLBACK_VERSION`, no side effects. The route passes the capability's `fromBuildVersionId`. Test-verified at the service seam.
*(Partially mitigates W5 from the #15 pass for the rollback side; the publish-side W5 conditional-update note remains.)*

### F2 — Unbounded operator metadata (Low — fixed in-diff)
`approvedBy`/`approvalNote` were stored unbounded. **Fixed:** capped at 200/500 chars with 400 on violation. Values are D1-bound parameters (no SQL injection surface).

### F3 — Silent denials on operator routes (Low — fixed in-diff)
Denied authorization attempts were invisible to operators. **Fixed:** each denial logs a `console.warn` line with route, reason and resource id — **never** token bytes or the secret.

### F4 — Needlessly broad lookup (Low — fixed in-diff)
Approval route's version lookup used a JOIN it didn't need; reduced to a single-table read (surface/complexity reduction only).

## 5. Severity summary
Critical 0 · High 0 · Medium 1 (F1, fixed in-diff) · Low 3 (F2–F4, fixed in-diff). No unresolved blocking findings.

## 6. Required remediation
None remaining in code. **Operational precondition before production use:** `wrangler secret put OPERATOR_CAPABILITY_SECRET` (random ≥ 32 bytes). Until set, both routes deny by default — safe to deploy, unusable, as intended.

## 7. Watch items
- **W-29a (Medium, operational):** the production secret above must be set (and rotated on operator compromise) before the routes are used; rotation instantly revokes all outstanding tokens.
- **W-29b (Low):** a future publication operator route/trigger must carry the same capability-token gating (bind `siteId + buildVersionId + artifactManifestHash + action + expiry`); `publishApprovedBuildVersion` currently has no production trigger.
- **W-29c (Low):** tokens are stateless with no revocation list; the 60-minute hard TTL ceiling bounds exposure. Acceptable for operator-only credentials.
- **W-29d (Low):** tokens travel in `Authorization` headers; Cloudflare does not log request headers by default — keep it that way in any future proxy/log pipeline.
- Standing items M1–M3, L2–L3, W1–W16 from the earlier CSO reports remain unchanged.

## 8. Final security verdict
**SECURITY OK WITH WATCH ITEMS** — issue #29 may advance to its dedicated commit. W4 (#15) is closed: Approval and Rollback operator routes cannot mutate anything without a valid, unexpired, sufficiently bound capability token, and no surface can mint one.

Commit issue #29, record the SHA in the implementation log and the issue, then proceed with the remaining pre-production items (W14 secret deletion runbook, H2 email transport wiring — both deploy-coupled).
