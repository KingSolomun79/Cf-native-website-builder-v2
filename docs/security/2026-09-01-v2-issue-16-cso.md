# CSO Security Sign-Off — Issue #16 (Deployment and Artifact Retention Lifecycle)

**Date:** 2026-09-01
**Scope:** Diff since `4b1cec7`: `src/domain/retention.ts` (new), `src/domain/assembly.ts` (preview supersession wiring), `src/domain/publication.ts` (deployment upsert reactivation on republish), `tests/v2-retention.test.ts`, `tests/v2-assembly-preview.test.ts` (expectation update).
**Reviewer:** AI-assisted CSO pass (morabeza-cso skill). Not a substitute for an external audit.

## 1. What was audited
Disposal rules for failed/superseded Preview Deployments and expired non-rollback published deployments, disposable R2 artifact pruning with benchmark retention, compact Build Record survival, and the supersession wiring in the preview deploy path.

## 2. Security scope
High-risk by classification (destructive operations: Worker deletion + R2 object deletion), but no new public routes — internal services only. No secrets, no visitor input, no payment flows.

## 3. Attack-surface summary
- D1 reads: `build_deployments`, `site_published_state`, `builds`, `build_versions`, `build_stage_artifacts`, `reference_evidence_packages`, `image_attempts`.
- Destructive: Worker deletion via the audited CF API path; R2 object deletion by D1-indexed keys.
- D1 rows are never deleted — history, approvals, provenance and cost ledgers survive by construction.

## 4. Findings

### Verified properties (no finding)
- **Protection completeness:** protected version ids (every Site's current Published Version + in-window Rollback Version) are computed from ALL sites before any deletion; the optional `buildIds` scope only narrows the candidate set, never the protection set (test-verified: current + rollback survive; expired non-rollback published removed).
- **Idempotence:** `status='deleted'` rows are skipped; repeated sweeps are no-ops; the publication upsert now reactivates the existing deployment row on republish instead of silently doing nothing.
- **Data-loss guards:** compact Build Records (outcome, QA scores, repair root causes, image cost ledger, prompt/model/schema provenance) are assembled purely from D1 rows that pruning never touches — verified after artifact removal.
- **No injection:** Worker names and object keys come from operator-side generation/D1 indexes, not visitor input; benchmark filtering is conservative (protects more, deletes less).

### W7 — Default deleter 404 tolerance (Fixed during this CSO pass)
The default Worker deleter originally threw on a 404 (Worker already gone externally), which would have blocked the row from ever being marked `deleted` — weakening the idempotence acceptance criterion in real environments. **Remediated in this diff:** 404 is now treated as already-deleted; other errors still fail the sweep safely (row stays unmarked and is retried). Retention tests re-run green.

### W8 — Scheduled-trigger exposure precondition (Watch item, Medium — gates exposure, not this scope)
Cleanup has no HTTP surface today. When it is wired to a cron/scheduled trigger or operator route, that entry point must not be publicly reachable (Workers cron triggers are internal by default; any route form must carry the operator HMAC or a capability token).

### W9 — Deletion ordering (Watch item, Low)
Workers are deleted before the row is marked `deleted`; a crash in between leaves an orphaned row that the next sweep resolves (deleter now tolerates the already-deleted case). Acceptable eventual consistency.
