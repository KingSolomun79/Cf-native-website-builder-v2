# CSO Security Sign-Off — Issue #31 (Capability-gated Publication operator route)

**Date:** 2026-09-01
**Scope:** Working tree vs `4795018`: `src/lib/operator-capability.ts` (new `publish` action), `src/routes/v2.publication-create.ts` (new), `src/index.ts` (route table), `src/domain/publication.ts` (`expectedArtifactManifestHash` mutation-boundary guard), `scripts/mint-operator-capability.mjs` (`publish` action), `tests/v2-operator-capability.test.ts` (publication route suite).
**Reviewer:** AI-assisted CSO pass (morabeza-cso skill). Not a substitute for an external audit.

## 1. What was audited
The first HTTP exposure of the third and last human release action — Publication (`POST /api/v2/build-versions/:buildVersionId/publication`) — and the extension of the #29 capability mechanism with its own action-bound token. This closes W-29b from the #29 CSO pass and the publish-side TOCTOU note (W5 from #15).

## 2. Security scope
High-sensitivity by classification: a new **authenticated operator route that makes content live on the public internet** (deploys the approved artifact to a workers.dev URL), reusing the existing `OPERATOR_CAPABILITY_SECRET` HMAC scheme. No new secret is introduced.

## 3. Attack-surface summary
- One new POST route, now the only HTTP mutation surface for publication (grep audit: `publishApprovedBuildVersion` previously had **no production caller**; the route is the sole trigger).
- Token verification reuses the audited #29 machinery: HMAC-SHA256 over `v2opcap/1:publish:{buildId}:{buildVersionId}:{artifactManifestHash}:{exp}`, timing-safe compare, strict bound-value charset (no `:` delimiter smuggling — `publish` cannot collide with `approve`/`rollback` in the canonical string), `exp` within `(now, now + 60 min]`, ≤ 4096 chars, fail-closed when the secret is unset.
- Minting stays offline-only; the mint script gained a `publish` branch mirroring `approve`. **No minting route exists**; `signOperatorCapability` remains unreachable from any handler.
- Generated Sites remain static-assets-only workers (no bindings, no secrets — pinned by `tests/v2-static-deploy.test.ts`): browser/generated-site code can neither read the secret nor obtain a token.

## 4. Findings

### Verified properties (no finding)
- **Action separation:** the action string is inside the signed canonical form, so an Approval or Rollback capability is structurally insufficient on the publication route (403 `CAPABILITY_INSUFFICIENT`), and a publish capability cannot Approve or Roll back. Test-verified for both directions of confusion available to this route.
- **Deny-by-default across all classes:** missing header, garbage, expired, wrong-secret and unset-secret all yield 401 with zero publication rows and untouched published state (test-asserted).
- **Binding sufficiency:** the token must bind the exact `buildId`, the exact `buildVersionId` from the path, and the version's **current** manifest hash; wrong build, wrong version (including a sibling Build Version of the same Build) and stale-hash tokens are all 403.
- **Authorization strictly precedes mutation:** verify → action → resource binding → service call; no DB write happens on any denial path.
- **Domain ordering preserved after authorization:** unapproved version is 409 `NOT_APPROVED`; missing candidate bytes in immutable storage is 500 `PUBLISH_FAILED` with a failed-attempt row and no partial publish; unknown version is 404.
- **TOCTOU closure (publish side):** the route authorizes against the current manifest hash, and `publishApprovedBuildVersion` now re-enforces the authorized hash at the mutation boundary (`expectedArtifactManifestHash`, mirroring rollback's `expectedCurrentBuildVersionId`) **plus** the standing approval-hash guard. The mutation targets exactly the `buildVersionId` from the path — there is no candidate re-selection anywhere, so authorization of one version cannot mutate another.
- **No regeneration:** the deployed files come from immutable storage paths derived from the approved manifest; the route adds no generation path (test-asserted: Build Version count unchanged through publication).
- **Idempotent retry semantics:** re-publishing the exact current Published Version with a fresh token is a read (200, same publication id, no new row) — the permitted operational retry only.
- **Cross-signer agreement:** the Worker (WebCrypto) and mint-script (node:crypto) publish canonical forms are pinned byte-for-byte by a new known-answer vector.
- **No secret/token leakage:** denials log route, reason and resource id only; responses never echo token bytes or the secret. All SQL is parameterized.

### F1 — Declared-manifest hash vs recomputed hash (Low — pre-existing, accepted)
`artifactManifestHash` is a field *declared inside* the stored manifest JSON, not recomputed from it at publish time. An attacker with direct R2 write access could rewrite a manifest (keeping the declared hash, changing the file list) plus the referenced file objects. **Not introduced by #31** — it is the pre-existing #15 storage-trust model; product paths write manifests via `putImmutableObject`/D1 immutability triggers, and an R2-level attacker can already overwrite live-site assets directly, making this route a non-preferred target. Left as a standing integrity watch item (W-31b), not a blocker.

### F2 — Duplicated `ERROR_STATUS` map (Low — hygiene, accepted)
The map is duplicated across the three operator routes. Code duplication only; no security delta. Acceptable at this size.

## 5. Severity summary
Critical 0 · High 0 · Medium 0 · Low 2 (F1 pre-existing storage-integrity watch item; F2 hygiene). No unresolved blocking findings.

## 6. Required remediation
None. Operational preconditions are unchanged from #29: `OPERATOR_CAPABILITY_SECRET` must be set (random ≥ 32 bytes) on the V2 production Worker before the route is usable; until then it denies by default, which is the intended safe state.

## 7. Watch items
- **W-31a (Medium, operational):** production publication authority now exists behind a token with a 60-minute TTL. Keep TTLs short in runbooks (30 min default in the mint script) and rotate the secret on operator compromise — rotation revokes all outstanding tokens.
- **W-31b (Low, standing):** manifest-hash integrity is declared-not-recomputed (F1). If storage-level adversary concern ever materializes, add a publish-time recomputation of the manifest hash over the assembled bytes.
- **W-31c (Low):** operator routes have no rate limiting, consistent with the accepted #29 posture (unguessable HMAC credentials; brute force infeasible; fast-fail 401 path).
- W-29a/d and standing items from earlier CSO reports remain unchanged.

## 8. Final security verdict
**SECURITY OK FOR CURRENT SCOPE** — issue #31 may advance to its dedicated commit. W-29b is closed: Publication now requires its own valid, unexpired, exactly-bound capability token; no surface can mint one; and the publish-side TOCTOU class is enforced at the mutation boundary.
