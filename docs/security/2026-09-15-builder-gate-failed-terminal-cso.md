## 2. Security scope

Auth, authorization, secrets, public endpoints, payment flows and webhooks are
untouched. The diff touches: deterministic validation of model output
(website-builder), a lifecycle terminal mapping (pipeline), and the admin
notification composer selection that follows from it.

## 3. Attack-surface summary

- Model-authored strings (CSS selector tokens / selector preludes) propagate
  into `ai_stage_runs.error_summary`, `build_workflow_events.detail`, the
  workflow output reasons and the GENERATION_FAILED email body. This is the
  pre-existing propagation class for ALL deterministic validator failures
  (meta-marker, CSS gate, schema errors) — the correction adds one more
  producer of the same kind, with the same bounds (detail slice 400, email
  reason slice 300, tokens constrained to `[a-zA-Z_-][\w-]*`; selector
  preludes whitespace-collapsed). No HTML rendering surface consumes these:
  the admin dashboard renders neither event details nor outcome reasons, and
  the email is text/plain to the operator-configured mailbox
  (`WAZIBIZ_ADMIN_EMAIL`), never a visitor-controlled recipient.
- Lifecycle writes: the FAILED event uses the existing
  `appendBuildWorkflowEvent` path; `FAILED` is a member of the reconciliation
  sweep's `TERMINAL_BUILD_STATES`, so `failBuildForWorkflowTermination`
  remains a no-op on these builds (no double-terminal).
- No new bindings, env vars, secrets, routes or retries. Nothing is deleted.

## 4. Findings

None blocking. Notes:

1. Watch item (Low, pre-existing class): model-derived selector text in
   operator-facing failure strings. Bounded, operator-only, no HTML surface.
   No action for this correction.
2. The FAILED event append is not itself idempotent (a full step replay after
   a lost step-cache write could append a second identical FAILED event).
   Identical to the pre-existing review/blueprint terminal paths; the state
   update is idempotent and duplicates are audit noise only. No action.
3. The correction strictly TIGHTENS the builder contract (earlier, per-file
   detection; truthful terminal). No gate is relaxed and no fallback path was
   introduced; the end-of-stage DOM-first gate remains as defense in depth.

## 5. Severity summary

patterns, one now with one more producer of the same bounded strings).
