## 1. What was audited
Frozen five-case benchmark identity (checksums, immutability, swap rejection), the full-pipeline benchmark runner with injectable seams, PASS/failure calculation against the USD 3 hard gate, run recording with provenance/root cause, and two correctness fixes surfaced by the golden-path run.

## 2. Security scope
No new public routes, secrets, payment flows or visitor input. Internal harness services only; benchmark briefs contain fictional business data. Sensitive aspect: integrity of frozen benchmark inputs (anti-target-swapping) and pipeline cost bounds.

## 3. Attack-surface summary
- D1: `benchmark_cases` (immutable after freeze), `benchmark_runs` (append-only + completion transition).
- Identity: sha256 checksums over the frozen evidence structure and screenshot bytes, verified at freeze and before every run.
- Pipeline: full V2 stage chain with operator-injected dependencies; spend bounded by the existing image hard gate.

## 4. Findings

### Verified properties (no finding)
- **Anti-swap:** `benchmark_cases` rows carry evidence+screenshot checksums with UPDATE/DELETE triggers; `freezeBenchmarkCases` is idempotent and rejects any drift against already-frozen rows (`BENCHMARK_ALREADY_FROZEN_DIFFERENT`); every run re-verifies identity (`BENCHMARK_IDENTITY_MISMATCH` on mutated evidence or screenshot). Tests prove mutated regions/screenshot bytes and storage-level tamper attempts are rejected.
- **PASS integrity:** PASS is computed only from automated Release Ready + zero manual edits + spend ≤ USD 3.00; the golden-path test proves no approval/publication rows are created for a benchmark run.
- **Provenance/audit:** every run persists prompt/model/schema versions from `ai_stage_runs`, QA summary, root cause (PRD §45 taxonomy) and image spend; run rows are delete-protected.
- **Correctness fixes (no security impact, verified by tests):** Technical Preflight no longer false-flags `max-width` (only standalone oversized fixed `width`); generation no longer double-freezes `builds/{id}/v{n}/source/*` keys — assembly remains the sole freezer of the resolved candidate, eliminating an immutable-key conflict.

### W10 — Benchmark screenshot staging put is mutable (Watch item, Low)
`persistFrozenScreenshot` uses a mutable R2 put under `benchmarks/{case}/reference/screenshot.png`; identity verification checksums the in-code definition, not the stored object, so a (operator-side) overwrite of the staging object would not be detected by `verifyBenchmarkIdentity` before intake consumes it. Hardening for a later pass: content-verified immutable put (write-once, compare-on-conflict). Operator-only write path, so not blocking.

### W11 — Golden scripts live in tests only (Verified, no action)
`tests/helpers/benchmark-golden.ts` is test-only; production wiring must always inject real services. No production import path exists (verified by import graph).
