# CSO Security Sign-Off — Issue #32 (Configurable platform Sender Identity)

**Date:** 2026-09-01
**Scope:** Working tree vs `6b8832d`: `src/domain/form-service.ts` (env-resolved platform sender, fail-closed sender gate, config-boundary validation), `src/env.d.ts` (`WAZIBIZ_SENDER_EMAIL`), `wrangler.test.jsonc` + `wrangler.jsonc` staging env (test/staging var values; production deliberately unset), `tests/v2-form-service.test.ts` (new #32 suite + fixture updates), `tests/v2-final-verification.test.ts` (fixture update), runbook/topology doc updates.
**Reviewer:** AI-assisted CSO pass (morabeza-cso skill). Not a substitute for an external audit.

## 1. What was audited
Removal of the hard-coded platform sender mailbox from product behavior: the default outbound `From` is now the `WAZIBIZ_SENDER_EMAIL` Worker var (configuration, not a secret), resolved and validated at the delivery boundary, with deterministic fail-closed behavior when missing or malformed. Retry semantics and the browser-never-controls-delivery contract were checked for regressions.

## 2. Security scope
Trust boundary on the **outbound email identity**: who controls `From`, `Reply-To` and the recipient; plus config validation at the Site Configuration boundary. No new secret is introduced (the value is a Worker var by design).

## 3. Attack-surface summary
- Same two surfaces as before (public `POST /api/v2/forms/submit`, cron retry sweep); the change is internal to sender resolution.
- `resolvePlatformSenderIdentity(env)`: trims, requires the anchored email pattern (`^[^@\s]+@[^@\s]+\.[^@\s]+$`, ≤ 320 chars — no whitespace/newlines, so no header-injection via the env value), returns null otherwise.
- Precedence: explicit Site Configuration `sender_identity` (future verified Business-owned sender) → `WAZIBIZ_SENDER_EMAIL` → fail-closed. Nothing else can set `From`.
- `attemptEmailDelivery` gained a sender gate before any transport call: invalid/empty sender records a `transient_failure` ledger row (`error_detail` names `WAZIBIZ_SENDER_EMAIL`) and sends nothing.
- Retry: the recorded sender stays authoritative (existing Email Delivery contract); only the empty sentinel (unresolvable at the previous attempt) re-resolves from the current environment.

## 4. Findings

### Verified properties (no finding)
- **No hard-coded mailbox anywhere in product behavior** (grep audit: `DEFAULT_PLATFORM_SENDER_IDENTITY` and its address are gone from `src/`; only explicit example literals remain in tests/docs, clearly labelled).
- **Fail-closed, deterministically:** missing, empty, malformed and injection-shaped env values all yield a null resolution, a `transient_failure` ledger row, and **zero transport calls** — no fallback address, no visitor `From`, no degraded arbitrary sender. The Accepted Submission stays accepted (PRD 37: acceptance never depends on delivery).
- **Browser cannot influence the sender:** payload contract unchanged (`from`/`sender`/`recipient`/… rejected as `BROWSER_PAYLOAD_CONTRACT` — now explicitly test-covered); the effective sender derives only from Site Configuration override or the Worker env; the submit response (`{accepted, submissionId}`) discloses nothing (test-asserted).
- **Config-boundary validation:** `upsertSiteConfiguration` now rejects invalid `formDestination` and invalid explicit `senderIdentity` (`SENDER_IDENTITY_INVALID`, 400) before any write — closing a small pre-existing gap where malformed addresses could be stored.
- **Retry semantics preserved:** a recorded non-empty sender wins over a changed environment (sender captured at acceptance); the empty sentinel heals from a fixed environment through the bounded retry without visitor resubmission — test-verified in both directions.
- **Email Service adapter receives only validated values** (`from` passed trimmed after gate): test-verified end-to-end through the native binding double.
- **Environment separation:** test config carries an explicitly-labelled example address (`noreply@staging.wazibiz.example`); staging env carries an explicit staging example; **production defines no value** until the operator approves a mailbox (#33/#27) — `wrangler deploy --dry-run` confirms.

### F1 — Fail-closed sender gap consumes the bounded retry budget (Low — accepted, documented)
While misconfigured, each cron sweep records an attempt; after `MAX_DELIVERY_ATTEMPTS` (5) the submission terminal-fails as `permanent_failure` even though only configuration was wrong. **Accepted:** deterministic fail-closed is the required behavior, the ledger names the exact cause (`WAZIBIZ_SENDER_EMAIL missing or malformed`), and ~50 minutes of sweep window plus the durable Accepted Submission give the operator time to fix and redeploy. Watch item W-32a tells #30 to verify the var before the first real submission.

### F2 — Stale pre-#32 Site Configuration rows carry the old placeholder as an explicit override (Low — operational, tracked for #33)
Rows created before #32 stored `noreply@mail.wazibiz.example`, which now behaves as an explicit override shadowing the env value. Production is a fresh database (no rows); the staging smoke row must be re-upserted during #33 staging verification (prepared as a #33 task: re-upsert `site_configurations` for the smoke site so the platform default applies). No code remediation needed.
