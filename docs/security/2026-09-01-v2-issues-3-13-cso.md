## 1. What was audited

- Domain services: `src/domain/*` (lifecycle, revision, ai-boundary, prompt-contract, reference-*, visual-blueprint, implementation-planner, site-generator, image-pipeline, form-service, assembly, technical-preflight, qa-*, release, stage-artifacts, artifact-keys).
- Migrations 0017–0025 (immutability triggers, ledger tables).
- Reused infra touchpoints: `lib/crypto` (HMAC, timing-safe compare), `lib/assets` (immutable R2 puts), `lib/ai-gateway` (GatewayMeta extension), `lib/publish` (default preview deployer path).

## 2. Security scope

Touches: public endpoints, webhook-style signed intake, secrets/config handling, D1/R2 data access, third-party AI/KIE integrations, worker deployment plumbing. No payment flows. Auth model: operator actions HMAC-signed (`X-Signature`, timing-safe); browser form endpoint validated by origin/schema/Turnstile/rate; reads protected by unguessable UUID capabilities.

## 3. Attack-surface summary

- **Public:** form submit (multi-tenant), PII read APIs keyed by UUID.
- **Signed:** onboarding intake, build start, revision requests.
- **Background:** workflow boundary, delivery retry sweep, image waves.
- **Secrets:** WEBHOOK_SECRET, provider keys (existing), TURNSTILE_SECRET_KEY (new, undeclared), CF deploy token (reused).
- **Third parties:** LLM providers (business facts egress), KIE (image generation), Cloudflare API (deploy).

## 4. Findings

### H1 — Default preview deployer inherits V1 contact-worker + secret injection (Verified risk, High)
`src/domain/assembly.ts` default deployer calls `lib/publish.createWorker(env, name, jwt, "")`. `createWorker` always injects `generateContactWorkerScript(contactEmail)` as the worker's main module and binds `SMTP2GO_API_KEY` as a `secret_text` binding (`src/lib/publish.ts:238,292`). Production preview deploys would therefore ship a per-site mail worker with an empty recipient and propagate the SMTP2Go secret into every preview Worker — violating PRD §35 and the migration manifest (REPLACE → DELETE BEFORE V2 RELEASE). Tests only exercise injected deployer stubs, so this path is unexercised. **Impact:** secret propagation to per-site workers; obsolete V1 product path ships. **Fix:** write a V2 static-assets-only deploy path (no contact script, no SMTP2GO binding) before enabling production preview deploys; keep `publish.ts` contact coupling quarantined until the Phase-11 removal.

### H2 — Form Service has no production email transport wired (Verified risk, High — operational, fail-closed)
The default transport in `src/domain/form-service.ts` reads `globalThis.__WAZIBIZ_EMAIL_TRANSPORT_URL__`, which nothing sets in production. All deliveries classify transient → bounded retry → `permanent_failure`. Accepted Submissions remain durable (correct per PRD §37) and nothing falsely reports success, but no email can ever deliver until the Cloudflare-native transport endpoint is configured. **Fix:** wire the real transport (env-declared binding/var) before accepting production form traffic.

### M1 — Unauthenticated PII reads on lifecycle GET APIs (Likely risk, Medium)
`GET /api/v2/site-generations/:id` and `GET /api/v2/builds/:id` return Business facts (name, contact email, address, socials) with no auth; protection is unguessable `crypto.randomUUID()` ids. Acceptable as capability URLs pre-launch; V1 used signed tokens for actions. **Fix before production:** require the operator HMAC (or a scoped capability token) on reads, or strip contact facts from public read models.

### M2 — Form rate-limiting gaps (Likely risk, Medium)
Per-site+IP limit (5/10 min) is check-then-act (small concurrency bypass) and there is no aggregate per-site cap, so rotating-IP actors can insert unbounded `form_submissions` rows (D1 write cost) and trigger deliveries. Turnstile defaults to off (`turnstile_required` default 0). **Fix:** atomic counter or INSERT-triggered limit, per-site daily ceiling, and default Turnstile-on for production sites.

### M3 — Model-generated HTML ships without a script allowlist (Likely risk, Medium)
Preflight validates structure only. A malicious/compromised Reference page could prompt-inject the generator into emitting attacker `<script>` that ships to site visitors (structural schema validation does not bound content). Reference URLs are operator-supplied (semi-trusted), and output is static-only by construction. **Fix before real reference use:** script/src allowlist or strict CSP at preflight.

### L1 — Undeclared env contract (Low)
`TURNSTILE_SECRET_KEY` read via env cast; transport URL via a `globalThis` property — neither declared in `env.d.ts`/`wrangler.jsonc`. Fail-closed, but config drift risk (Turnstile-required site without secret = all submissions 403). **Fix:** declare both properly.

### L2 — Image provider bytes unvalidated (Low)
KIE "complete" results are persisted as `image/webp` without magic-byte or size checks (memory/cost exposure; forced content-type limits XSS). **Fix:** validate signature + cap size before persist.

### L3 — Hygiene (Low / watch)
Unsalted SHA-256 of client IP stored (low-entropy; salt with a secret). If `attemptEmailDelivery` throws after the durable insert, the visitor sees a 500 despite acceptance (safe direction — no false success; consider returning 202 once accepted). Business facts egress to configured LLM providers — confirm provider data-handling posture. Cross-origin native form POST works; if JS-fetch submission is added later, add CORS restricted to allowed origins.

## 6. Required remediation (before production traffic)

1. H1: V2 assets-only deploy path; no contact-worker script, no SMTP2GO binding in preview/published workers.
2. H2: wire the real Cloudflare-native email transport behind a declared env var/binding.
3. M1: auth (HMAC or capability token) on lifecycle read APIs, or remove PII from public reads.
4. M2: atomic + aggregate rate caps; Turnstile default-on.
5. M3: script allowlist / CSP enforcement in Technical Preflight.

## 7. Watch items

- L1 env declarations; L2 image byte validation; L3 IP-hash salting, 500-after-acceptance path, LLM provider data policy, future CORS needs.
- Prompt-injection from Reference content is schema-bounded but not content-bounded (see M3).
- Secrets remain bindings-only; no secrets in generated assets verified for all new code paths.

## 8. Final security verdict

**SECURITY OK WITH WATCH ITEMS** for the audited scope (merge/test readiness of issues #3–#13: signed operator routes, timing-safe HMAC, immutable artifacts with R2 `onlyIf` guards, D1 immutability triggers, fail-closed Turnstile/transport, browser payload contract preventing delivery control, durable-then-report acceptance). **H1/H2 must be remediated before preview deployment or form delivery carry production traffic.**

## Addendum — H1/H2 remediation (2026-09-01, same session)

### H1 remediated — V2 assets-only deploy path (verified by regression tests)

- `src/lib/publish.ts`: shared deploy helpers extracted (`ensureWorkerId`, `deployVersionAndEnable`) and a new **`createStaticAssetsWorker(env, workerName, uploadJwt)`** creates Worker versions with **assets only** — no `main_module`, no `modules`, no `bindings`, no contact-worker script, no `SMTP2GO_API_KEY`. The V1 `createWorker` keeps its behavior for the legacy pipeline only.
- `src/domain/assembly.ts`: the default preview deployer now calls `createStaticAssetsWorker`; the `createWorker(env, name, jwt, "")` path is gone.
- `tests/v2-static-deploy.test.ts` (2 tests) exercises the **real default deploy path** against a stubbed Cloudflare API and asserts the version payload contains `assets` only — `bindings`/`modules`/`main_module` absent, no `SMTP2GO`/`secret_text`/`contact` strings anywhere in the deploy call sequence — plus correct deployment-row pinning of the artifact manifest hash.
- Grep check: no `src/domain/` code references `SMTP2GO` or the V1 `createWorker`.

### H2 remediated — declared, wired transport (fail-closed preserved)

- `src/env.d.ts`: `WAZIBIZ_EMAIL_TRANSPORT_URL` (var), `WAZIBIZ_EMAIL_TRANSPORT_TOKEN` (secret), `TURNSTILE_SECRET_KEY` (secret) are now declared — this also closes L1's undeclared-env finding.
- `src/domain/form-service.ts`: `createDefaultEmailTransport(env)` reads the declared endpoint, sends optional bearer auth, and classifies 5xx as transient / 4xx as permanent; unset endpoint still fails closed as transient with bounded retry. `attemptEmailDelivery` uses it by default; the `globalThis` hack is gone. Turnstile secret access is typed.
- `wrangler.jsonc`: `WAZIBIZ_EMAIL_TRANSPORT_URL` documented as an empty-default var — **operations must set it (plus the transport token secret) before production form traffic**, otherwise delivery records bounded `permanent_failure` while Accepted Submissions stay durable.
- `tests/v2-form-service.test.ts` +3 tests: unconfigured fail-closed, success/auth/failure classification via stubbed router, and end-to-end acceptance delivering through the env-configured transport.
